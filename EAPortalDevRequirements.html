EA Portal — Client-Side Development Requirements

Full-stack / frontend scope for a developer continuing work on the EA Portal persona dashboards.

ProjectEA Portal
ScopeAuth, data model, API, frontend logic
StatusDev handoff draft
DateOctober 2026

1. Auth & Routing

  • Persona-based auth/session resolving to one of: Admin, Manager, Staff, Client, Sales Prospect — plus a 404 fallback for unmatched or unauthorized routes.
  • Route guards per persona (a Client must not reach Sales/Admin views, and vice versa).
  • Deep-link support into a specific project and journey stage.
  • Remove any remaining references, routes, or nav entries pointing to the deleted Developer dashboard.
  • Confirm the 404 page catches stale/removed Developer links.

2. Data Model

Project

  • id, title (expect truncation-safe strings — UI renders titles on a fixed 2-line display).
  • currentPhaseName, currentPhasePercent (e.g. "Interior Design — 62%").
  • Ordered stage/milestone list.
  • type flag distinguishing real client/purchased projects from Sales Prospect (demo) projects — progress is unlocked and real for Sales Prospect, locked to true completion for Client.

Stage

  • name, order, progressPercent, isCurrent boolean.
  • Associated media: fullscreen preview video asset (Sales Prospect stages) vs. drawing/document links (real Client stages).

Team / Avatars

  • API returns the full assignee list (name, avatarUrl); frontend caps display to first 2 + "+N" overflow — don't pre-truncate server-side.

3. API Endpoints

GET stage mediaFullscreen preview video (Sales) or drawing/document asset (Client)All personas

4. Frontend Logic

  • Conditional click handler on journey stage cards: Sales Prospect → open fullscreen video modal; Client/real project → navigate to drawing page. Branch on project.type === 'prospect', not persona alone, in case Sales users ever view real projects.
  • Current-stage highlight (crimson) driven by stage.isCurrent from data — applied consistently to footer, label, status badge, and "Add Services" CTA.
  • Card rendering shared between Client and Sales dashboards — same title truncation, avatar cap, and phase-caption row logic. Prefer one shared component over duplicated markup.
Note: the Sales dashboard's stage ring and progress values are real, unlocked data — not forced to 100% — and the listing cards must reflect each project's actual timeline, not a static demo state.

5. Cleanup

  • Remove EAPortalDashboardDeveloper references from build config, imports, and persona switcher.
  • Audit nav and any hardcoded persona lists for the now six-persona set: Admin, Manager, Staff, Client, Sales Prospect, 404.
